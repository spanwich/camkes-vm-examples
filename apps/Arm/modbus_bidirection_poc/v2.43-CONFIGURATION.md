# v2.43 Configuration Summary

## Version: v2.43-BREADCRUMB-ONLY (2025-10-12)

### Overview
This version implements ultra-minimal breadcrumb tracing to debug the race condition Heisenbug that causes crashes at NULL pointer addresses (0x4, 0x8, 0x10) in SILENT mode and local console.

### Key Characteristics
- **Output**: Breadcrumbs only (`B<id>\n` format) + initialization messages
- **Debug Level**: SILENT mode with all verbose traffic/metadata/packet output disabled
- **Purpose**: Identify exact crash location without affecting race condition timing

**Root Cause**: Net1 closes the connection before Net0 finishes writing the response. Classic use-after-free race condition.

## Known Issues

### Critical Race Condition (Root Cause Identified)
**Problem**: Net1's `inbound_tcp_recv_callback` closes the TCP connection (frees PCB) before Net0's `outbound_ready_handle` finishes writing the response.

**Evidence**:
1. Breadcrumb sequence: B1011 (close) → B3009 (write)
2. lwIP assertions:
   - "tcp_write: no pbufs on queue => both queues empty" (line 344 tcp_out.c)
   - "pbuf_free: p->ref > 0" (line 753 pbuf.c)
3. Crashes at addresses 0x4, 0x8, 0x10 (corrupted PCB structure)

**Solution Options**:
1. Don't close connection in Net1's callback, let Net0 close after writing
2. Add reference counting to PCB lifecycle
3. Use completion flag to ensure Net0 is done before Net1 closes
